# 维修记录统计报告说明

## 概述

从设备出勤统计表的单元格批注中提取维修记录，经台账匹配和故障分类后，生成包含 10 个统计 sheet 的 Excel 报告。

- **输入**：设备出勤统计表（单文件或文件夹）
- **输出**：`维修记录统计.xlsx`（10 个 sheet）
- **排序**：全表按日期 → 标准设备名称排序

---

## Sheet 1：维修明细

全量记录（含非故障），每条维修事件一行。

| 列 | 类型 | 说明 |
|----|------|------|
| 日期 | YYYY-MM-DD | 排序主键 |
| 原始设备名称 | 文本 | 出勤表中的原始车号 |
| 标准设备名称 | 文本 | 台账匹配后的标准名，排序次键 |
| 设备型号 | 文本 | 从标准名提取（去除 `XX#NNNN` 后缀） |
| 原因 | 文本 | 检修 / 点检 / 保养 |
| 班次 | 文本 | 白班 / 夜班 / 未标注 |
| 大类 | 文本 | 20 大类之一；计划保养保留分类，纯噪声为空 |
| 小类 | 文本 | 102 小类之一；每条记录只保留一个小类 |
| 分类方式 | 文本 | 规则 / ML辅助 / 待确认 / 噪声过滤 |
| 分类置信度 | 数值 | ML 辅助分类的置信度；规则分类为空 |
| 是否故障 | 文本 | 是 / 否 |
| 维修内容 | 文本 | 批注原文，无批注则为空 |
| 工时_分钟 | 数值 | 单元格中的维修工时 |

## 输出模式

### 默认模式

生成单个文件：`维修记录统计.xlsx`，包含上述 10 个 sheet。

### 按年份拆分模式

勾选「按年份拆分输出」后，每年生成独立文件，另附汇总文件：

```
维修记录统计_2023年.xlsx
维修记录统计_2024年.xlsx
维修记录统计_2025年.xlsx
维修记录统计_2026年.xlsx
维修记录统计_汇总.xlsx      ← 包含全部年份数据
```

每个年度文件和汇总文件均包含完整的 10 个 sheet。

---

## Excel 输出格式

- 表头：加粗、蓝底白字（#4472C4）、居中对齐、自动换行
- 数据行：交替底色（白色 / #F2F7FB）
- 列宽：自适应内容（支持中日韩宽字符），最小 8，最大 50
- 日期列：`yyyy-mm-dd` 格式
- 百分比列：`0.00%` 格式
- 小时列：`0.0` 格式
- 冻结首行
- 自动筛选

---

## 故障率计算

```
故障率 = 总故障分钟 ÷ (统计跨度天数 × 24 × 60)
```

- **统计跨度天数** = 设备首次出现日期到最后出现日期的天数 + 1
- 基于全量记录（含非故障）计算跨度，而非仅故障记录
- 结果为小数，Excel 中显示为百分比格式

---

## 分类规则

默认 20 大类、102 小类。分类前先清理作者、翻译器、发动机小时数等元数据，
再综合关键词、组合关键词、排除关键词、正则和显式优先级，全局选择一个大类/小类。

| 大类 | 小类数 |
|------|--------|
| 发动机系统 | 9 |
| 变速箱与变矩器 | 5 |
| 传动与车桥 | 4 |
| 液压系统 | 9 |
| 低压电气与控制 | 8 |
| 电驱动系统 | 5 |
| 制动系统 | 5 |
| 转向系统 | 4 |
| 悬挂与车架 | 4 |
| 轮胎与车轮 | 5 |
| 履带与行走机构 | 4 |
| 工作装置 | 5 |
| 驾驶室与车身 | 5 |
| 空调与暖风 | 4 |
| 集中润滑系统 | 4 |
| 结构件与通用机械 | 4 |
| 电缆与卷筒系统 | 3 |
| 安全消防与事故 | 5 |
| 计划保养与非故障作业 | 7 |
| 其他/待确认 | 3（信息不足、仅现象未定位、多系统/需拆分） |

可通过 Excel 配置模板自定义（管理 → 维修分类配置 → 导出/导入）。
计划保养会继续出现在维修明细中，但不会进入故障统计。

### “其他/待确认”的 ML 二级分类

系统可加载 `models/maintenance_classifier.joblib`，对规则分类后仍属于
“其他/待确认”的故障记录进行二次识别。模型使用字符级 TF-IDF、分层线性分类
（先大类、后小类）及类别中心相似度校验。

- 规则分类始终优先，模型不会覆盖已有规则结果。
- 只有大类、小类两层置信度、类别间隔和中心相似度均达标时才回填。
- 短文本、含“正常”的记录及低置信度结果继续保留为待确认。
- ML 回填结果在维修明细中标记为 `ML辅助` 并保留置信度，便于复核。
- Flet 和 Tauri 的“维修记录处理”均默认开启“机器学习辅助识别”，可在处理前关闭。
- CLI 可用 `--no-ml` 关闭；桌面安装包内已包含当前生效模型，无需单独复制模型文件。

重新训练：

```bash
uv run maintenance-train 全部设备维修明细汇总.xlsx \
  --llm-checkpoint 待确认维修记录_LLM标注.checkpoint.jsonl \
  --llm-input 待确认维修记录.xlsx \
  --llm-record-id-column 原始记录ID \
  --llm-min-confidence 0.90 --llm-min-agreement 0.75 \
  --min-confidence 0.80 --min-margin 0.30
```

训练报告保存在模型同目录的 `maintenance_classifier.metrics.json`。该报告衡量
模型与高确定性规则标签的一致性；真实业务准确率仍应通过人工标注样本验证。
同一记录被重复调用标注时，训练程序会先在记录粒度合并，再在规范化内容粒度
投票，避免重试次数不同造成样本权重失真。当前随 v2.0.0 发布的模型指标如下：

- 训练样本：47,630 条
- 可训练分类：84 个
- 留出集准确率：83.99%
- Macro F1：80.48%
- 安全接收覆盖率：37.36%
- 安全接收准确率：97.84%

“转向系统 → 连杆/球头/转向节”当前去重后的可靠样本不足 20 条，未进入 ML
训练类别，但明确关键词仍由规则正常识别，不影响该分类在体系中的保留。

### 调用大模型标注待确认记录

`maintenance-llm-label` 支持 OpenAI 兼容的 Chat Completions 接口。默认每次
请求 50 条，最大也限制为 50 条；每批成功后立即写入 checkpoint，可中断续跑。

建议通过环境变量传递凭据，避免 API Key 出现在终端历史和进程参数中：

```bash
export MAINTENANCE_LLM_URL="https://example.com/v1/chat/completions"
export MAINTENANCE_LLM_API_KEY="your-api-key"
export MAINTENANCE_LLM_MODEL="your-model"
```

也可将以上三项写入项目根目录的 `.maintenance_llm.env`。脚本会自动读取该文件，
且命令行参数或进程环境变量的优先级更高；该文件已加入 Git 忽略列表。

先检查候选数和预计调用次数，不发送请求：

```bash
uv run maintenance-llm-label 全部设备维修明细汇总.xlsx \
  --model your-model \
  --category-column 维修分类 \
  --dry-run
```

确认后正式标注：

```bash
uv run maintenance-llm-label 全部设备维修明细汇总.xlsx \
  --model your-model \
  --category-column 维修分类 \
  --context-columns 类型,车号 \
  --batch-size 50
```

对于新版处理结果，分类列为 `大类`，无需额外指定 `--category-column`。输出增加
`LLM大类`、`LLM小类`、`LLM置信度`、`LLM理由`、`LLM标注状态`。模型输出会按
当前分类体系校验；缺失记录、无效分类或非 JSON 响应会自动重试。

也可以直接指定 URL 和 API Key：

```bash
uv run maintenance-llm-label input.xlsx \
  --url "https://example.com/v1/chat/completions" \
  --api-key "your-api-key" \
  --model your-model
```

使用 Azure 等 `api-key` 请求头时：

```bash
uv run maintenance-llm-label input.xlsx \
  --url "完整接口URL" \
  --api-key "your-api-key" \
  --api-key-header api-key \
  --api-key-prefix "" \
  --model deployment-name
```
